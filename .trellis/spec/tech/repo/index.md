# Repository Package Map

These guidelines describe the current TrellisKerminal repository shape and how
package keys in `.trellis/config.yaml` map to source code and specs.

## Purpose

Keep Trellis package/spec routing aligned with the actual repository so
`get_context.py --mode packages`, task package binding, and future AI sessions
load the right guidance.

## Package Map

| Package key | Path | Package name | Spec path | Purpose |
| --- | --- | --- | --- | --- |
| `cli` | `packages/cli` | `trellis-kerminal` | `.trellis/spec/cli/**` | The only publishable package: user-facing CLI, core domain modules (`src/core/`), templates, migrations, release scripts, and platform configurators. |

The former `core` package (`@zhiwenliu/trellis-core`) was merged into
`packages/cli/src/core/` at 0.7.0; the `core` spec at
`.trellis/spec/core/**` still describes those modules. The `docs-site`
package and the `docs-site` / `marketplace` git submodules were removed — docs
now live in `docs/` inside this repo, and the `docs-site` spec layer was
removed with them.

## Layout

- The repo is a single-package repo: `pnpm-workspace.yaml` exists only so
  pnpm 10 discovers `packages/cli` (`packages: ["packages/cli"]`); exactly one
  `packages/cli/package.json` is published to npm as `trellis-kerminal`.
- No git submodules remain.

## Contracts

- `.trellis/config.yaml` declares no `packages:` section — the project runs in
  single-repo mode. Spec layers are auto-discovered from `.trellis/spec/` as
  every directory except `guides` (`packages_context.py::_scan_spec_layers`),
  so `--mode packages` reports "Single-repo project (no packages configured)"
  while still listing the spec layers that exist on disk.
- Tasks created without `--package` have `package: null` (single-repo mode);
  existing tasks keep their frozen `task.json.package`.
- Package-context output is generated by
  `.trellis/scripts/common/packages_context.py`, which scans
  `.trellis/spec/<package>/<layer>/index.md` for each discovered package and
  `.trellis/spec/guides/index.md` for the shared guides.

## Checks

```bash
python3 ./.trellis/scripts/get_context.py --mode packages
git diff --check -- .trellis/config.yaml .trellis/spec
```

`--mode packages` must list exactly the spec-layer directories that exist on
disk (no entries for removed packages such as `docs-site`). If a future
checkout provides a package-map checker under the Trellis scripts directory,
run it as part of package-map validation. That helper is not currently
present in this repo.
